# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Termco is presented first to software developers who want one coherent workspace for terminal, files, code, Git, AI, local services, containers, and remote environments. Engineering leaders and platform teams are a secondary audience evaluating team composition, security controls, and organization profiles.

## Product Purpose

Termco is a terminal-first development environment that keeps local development, remote operations, built-in AI, coding agents, and product extensions in one inspectable workspace. The website should help a developer understand the product quickly, see the real interface working, and download the correct build for their platform.

## Positioning

Termco is not a fixed collection of features around a terminal. Its runtime is composed from independently updateable plugins that users and teams can inspect, replace, fork, disable, and extend without rebuilding the whole application.

## Operating Context

Developers move between terminal sessions, files, editor and LSP feedback, Git review, local Preview, containers, SSH rigs, port forwarding, workflows, built-in AI, managed coding agents, and external MCP clients. Termco keeps those activities tied to the currently selected project and environment.

## Capabilities and Constraints

- Available for macOS, Windows, and Linux, with WSL supported through the Windows experience.
- Application releases are published from `termco-ai/termco`; plugin releases are published independently from `termco-ai/termco-plugin-releases`.
- The public website includes a homepage, feature pages, downloads, documentation, changelog, about information, FAQ, and source links.
- Download actions should resolve the latest compatible GitHub release automatically by platform.
- Product demonstrations use real Termco captures from the existing product-presentation package.
- The website must not invent customers, testimonials, prices, benchmarks, or unreleased capabilities.

## Brand Commitments

- Product name: Termco.
- Canonical domain: `termco.app`.
- Use the current Termco icon and the application’s established Quiet Studio design language.
- Terax’s public site is a structural quality reference, not a visual identity to copy.
- Voice is direct, technically specific, calm, and developer-first.

## Product Principles

- Show the real product doing the work before explaining its architecture.
- Keep developer control and inspectability visible around AI and remote operations.
- Treat plugins as product ownership and composition, not a decorative marketplace.
- Make local-to-remote continuity concrete through one workspace story.
- Keep release and download information current without requiring a website redeploy.

## Accessibility & Inclusion

The website must support keyboard navigation, visible focus, reduced motion, readable contrast, semantic landmarks, responsive layouts down to 320px, captions or written context for video, and useful content when media cannot autoplay.
